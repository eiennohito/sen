# Crypto boundary

The application uses the unmodified installed LINE Chrome `ltsm.wasm` through
`src/runtime.rs`. The account net worker owns one runtime for signing, message
decryption, history and sends. `src/client/e2ee.rs` caches keys and channels;
a WASM exception poisons the runtime and requires replacement.

A complete native replacement remains blocked on proprietary SKB token and
private-key loading and opaque MID conversion. Plaintext-key primitive timings
from the removed trial do not establish compatibility at that boundary.
No native signing or serialized-key fallback is installed.

Media file crypto is native in `src/client/desktop/assets.rs` and
`src/client/desktop/upload.rs`: HKDF-SHA256 derives the AES-256-CTR and
HMAC-SHA256 keys. Authentication precedes decryption. The independent synthetic
`fixtures/media.json` is generated by `tools/generate-media-fixture.go` and
consumed by the asset tests.

`examples/crypto-harness.rs` (feature `harness`) verifies synthetic Letter
Sealing and signing fixtures against the installed module, with an optional explicit WASM override.
`tools/generate-fixture.go` generates the independent Go fixture. The app
instead discovers the installed extension and checks its required interfaces;
fixture pinning does not select the app's runtime module.

See [issues.md](issues.md) for remaining work and [HANDOFF.md](../HANDOFF.md)
for account and artifact constraints.
